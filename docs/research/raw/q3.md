### **1. G-Eval: Framework, Mechanics, and Form-Filling Recipe**

**G-Eval** is a reference-free or reference-based evaluation framework that replaces direct scoring prompts with an **Auto-Chain-of-Thought (Auto-CoT)**, **form-filling paradigm**, and **probability-weighted scoring** [1-5].

```
                     G-EVAL FORM-FILLING WORKFLOW
                     
Step 1: Task Intro + Evaluation Criteria
             │
             ▼
Step 2: Auto-CoT Prompting ──> LLM generates "Evaluation Steps"
             │
             ▼
Step 3: Assemble Form ──> [Task Intro + Criteria + Auto-CoT + Context + Output]
             │
             ▼
Step 4: Output Token Logprobs ──> p("1"), p("2"), p("3"), p("4"), p("5")
             │
             ▼
Step 5: Probability-Weighted Sum ──> Score = ∑ [ p(s_i) × s_i ] (Continuous 1.0–5.0)
```

1. **Auto Chain-of-Thought Generation**:
   Rather than requiring engineers to manually write detailed evaluation prompts for each custom metric, the user supplies a high-level **Task Introduction** and **Evaluation Criteria** [2, 6]. The LLM is prompted once with `Evaluation Steps:` to automatically generate structured, step-by-step instructions for judging the target text [2, 6-8].

2. **Form-Filling Paradigm**:
   The prompt concatenates the Task Introduction, Evaluation Criteria, Auto-generated Evaluation Steps, Input Context (or source document), and the Target Text to be evaluated [8-10]. The evaluator output is formatted strictly as a form (e.g., `Evaluation Form (scores ONLY): - Coherence:`) [9-12].

3. **Probability-Weighted Scoring Function**:
   Direct integer generation on a 1–5 scale exhibits two severe failure modes:
   * **Score Compression**: One integer (typically **3**) heavily dominates the distribution, causing low variance and weak alignment with human rankings [13-16].
   * **Integer Ties**: Models rarely generate fractional scores even when instructed, creating ties that mask subtle quality variations [14-16].

   G-Eval resolves this by inspecting the output token log-probabilities over the predefined score set \\(S = \{s_1, s_2, \dots, s_n\}\\) (e.g., tokens `"1"` through `"5"`), normalizing their probabilities \\(p(s_i)\\), and computing the expected value [5, 17-19]:
   \\[\text{Score} = \sum_{i=1}^{n} p(s_i) \times s_i\\]
   *API Fallback*: For closed models that restrict log-probability access, \\(n=20\\) samples are drawn at `temperature=1.0` to estimate the probability mass empirically [20, 21].

### **2. Best Practices for 1–5 Scale Design and Calibration**

* **Anchor Every Integer With Concrete Behavioral Criteria**:
  Generic labels (e.g., `"1 = bad, 5 = excellent"`) fail because LLMs exhibit inconsistent threshold boundaries. Explicitly anchor all five levels with specific conditions [22, 23]:
  * *Score 1 (Critical Failure / Harmful)*: Contradicts context, invents unverified claims, or omits urgent safety instructions.
  * *Score 2 (Inadequate)*: Partially answers the question but misses essential context or includes minor hallucinations.
  * *Score 3 (Acceptable with Caveats)*: Factually supported by the context, but suffers from phrasing ambiguity, wordiness, or omissions.
  * *Score 4 (Strong / Minor Flaws)*: Accurate and completely grounded; minor imperfections in clarity or formatting.
  * *Score 5 (Exemplary)*: Fully grounded in evidence, completely responsive to user intent, and includes clear attribution.
* **Include a Reference Answer as Grounding Anchor**:
  Evaluator models show substantially higher correlation with humans when a trusted reference answer is included in the prompt alongside the criteria [22-25]. Across benchmarks like FLASK and BiGGen Bench, reference-based evaluations systematically outperform reference-free scoring [24-27].
* **Require Verbal Feedback Before the Score Token**:
  Prompting the judge to generate a brief explanation/justification *before* outputting `[RESULT] <score>` yields higher scoring correlation with humans than emitting the score token directly [22, 23, 28, 29].

### **3. Bias Controls (Position, Verbosity, Self-Preference)**

Empirical investigations across 15 LLM judges and 150,000+ evaluation instances reveal distinct structural biases [16, 30]:

| Bias Category | Mechanism | Evidence & Findings from Sources | Recommended De-Biasing Technique |
| :--- | :--- | :--- | :--- |
| **Position Bias** (Primacy / Recency) | Systematically favoring solutions based on their order in the prompt [16, 30, 31]. | **Quality-Gap Dependent**: Position Consistency (PC) collapses when candidates are of comparable quality (\\(\delta_q \approx 0\\)) [30, 32, 33]. Position bias is **not** random variation (Repetition Stability \\(RS > 0.85\text{--}0.95\\)) [34, 35]. Prompt length has a negligible effect [30, 36, 37]. | 1. **Position Swapping**: Evaluate candidates twice (`[A, B]` and `[B, A]`); require consistency [38, 39].<br>2. **Inconsistency-as-a-Tie**: Mark position-inconsistent pairs as ties rather than discarding them [40, 41].<br>3. **Multi-Judge Majority Voting**: Ensembles of distinct model families cancel out individual position preferences on 95%+ of cases [42, 43]. |
| **Verbosity Bias** | Systematically rating long, detailed responses higher regardless of content quality [16, 44]. | Bidirectional stepwise regression confirms output length is a significant predictor of preference fairness [37, 44, 45]. | 1. **Length-Agnostic Rubrics**: Add explicit instructions not to penalize brevity.<br>2. **Pre-truncation**: Normalize word counts or strip extraneous disclaimers before evaluation. |
| **Self-Preference Bias** | Preferring text generated by the judge's own model family or training distribution [16, 46-49]. | G-Eval-4 assigns higher scores to LLM summaries than human summaries even when human judges prefer the human text [50-53]. Using an LLM judge as an RLHF reward signal risks severe model self-reinforcement [48, 53-55]. | 1. **Cross-Family Judges**: Use an evaluator from a different architecture family than the generator [56, 57].<br>2. **Open Fine-Tuned Judges**: Use specialized, open-weight evaluators like **Prometheus 2** (merged via DARE-Linear) [58, 59]. |

### **4. Sample Size, Confidence Intervals, and Human Validation**

* **Validation Metrics Against Human Ratings**:
  * **Spearman’s Rank Correlation (\\(\rho\\))**: Evaluates monotonic rank ordering alignment with human judgments [20, 60, 61]. G-Eval-4 achieves \\(\rho = 0.514\\) on SummEval and \\(\rho = 0.611\\) on QAGS hallucination benchmarks, outperforming traditional metrics [46, 60-65].
  * **Pearson Correlation (\\(r\\))**: Measures linear agreement between continuous score predictions and human ratings [63, 65-68]. High-capacity open models (e.g., Prometheus-2-8x7B) achieve \\(r = 0.555\\) with humans on FLASK, closing the gap with GPT-4 (\\(r = 0.679\\)) [67-72].
  * **Kendall’s Tau (\\(\tau\\))**: Measures concordant vs. discordant pairs [60, 61, 63, 65]. *Caution*: Direct integer scoring inflates Kendall’s Tau because ties are excluded from discordant counts; probability-weighted continuous scoring provides a more reliable evaluation [20, 60, 61, 63, 73, 74].
  * **Inter-Annotator Agreement (Cohen’s \\(\kappa\\) / Fleiss’ \\(\kappa\\))**: Human calibration studies report Fleiss' \\(\kappa \in [0.74, 0.80]\\) across relevance, coherence, completeness, and answer quality [75-77]. Annotator calibration sessions on practice documents resolve disagreements exceeding 2 Likert points via consensus [76, 78, 79].
* **Statistical Significance & Sample Size Guidelines**:
  * **Sample Size**: Benchmark evaluations use stratified golden test sets of **100–200+ validated queries** distributed across question categories (factoid, topical, comparative, multi-hop) [80-85].
  * **Stratification by Complexity**: Evaluating across document complexity tiers (low, medium, high length/vocabulary richness) ensures performance advantages hold consistently as difficulty increases [86-88].
  * **Stability via Cross-Validation & Bootstrap**: Report standard deviations using **5-fold cross-validation splits** of the query pool [89, 90] or paired bootstrap inference over queries to establish significance [91].

### **5. Concrete Implementation: 1–5 Humanitarian Q&A Judge**

In humanitarian assistance Q&A (e.g., disaster response protocols, ration distribution, medical supply points), **hallucinations or inaccurate logistics can cause immediate physical harm**. 

Below is a production-ready G-Eval implementation using **Auto-CoT, anchored 1–5 rubrics, reference context, and token logit probability extraction**:

```python
import math
from typing import Dict
from openai import OpenAI

client = OpenAI()

HUMANITARIAN_PROMPT = """You are an expert humanitarian aid assessment judge.
Your task is to evaluate the factual accuracy, evidence grounding, and operational safety of an assistance answer.

Context Documents (Verified Standard Operating Procedures):
{context}

User Emergency Query:
{query}

Candidate Response to Evaluate:
{response}

Evaluation Criteria:
Factual Grounding & Humanitarian Safety (1-5):
- Score 1 (Dangerous / Unusable): Output invents non-existent relief locations, provides false medical/water/ration distribution guidance, or directly contradicts the context.
- Score 2 (Severely Deficient): Contains major factual omissions, misleading logistics, or claims unsupported by the context that could misdirect beneficiaries.
- Score 3 (Marginally Acceptable): Factual core is derived from context, but contains minor ambiguities or caveats that require external clarification.
- Score 4 (Operationally Sound): Entirely faithful to the retrieved context; accurately reflects distribution points, safety caveats, and eligibility without hallucination.
- Score 5 (Exemplary): Complete, strictly faithful adherence to context; clear instructions; transparently indicates boundaries of available knowledge.

Evaluation Steps:
1. Carefully read the Context Documents and identify the authorized operational details (locations, hours, procedures).
2. Decompose the Candidate Response into individual factual propositions.
3. Cross-reference each proposition against the Context Documents to verify entailment.
4. Assess whether any unverified claim poses operational or safety risks.
5. Provide brief verbal reasoning, then output the final rating token.

Evaluation Form:
Reasoning: <detailed chain-of-thought checking claims against context>
[RESULT] (Score only: 1, 2, 3, 4, or 5)
"""

def evaluate_humanitarian_geval(context: str, query: str, response: str) -> float:
    prompt = HUMANITARIAN_PROMPT.format(
        context=context,
        query=query,
        response=response
    )
    
    # Request log-probabilities for top tokens at the result decision
    completion = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.0,
        max_tokens=350,
        logprobs=True,
        top_logprobs=10
    )
    
    # Scan generated tokens for the [RESULT] marker
    content_tokens = completion.choices.logprobs.content
    score_logprobs = None
    
    for i, token_info in enumerate(content_tokens):
        token_str = token_info.token.strip()
        if "RESULT" in token_str or token_str == "[RESULT]":
            # The next non-whitespace token contains the score distribution
            for next_token in content_tokens[i+1:]:
                clean_t = next_token.token.strip().replace(":", "").replace("]", "")
                if clean_t in {"1", "2", "3", "4", "5"} or next_token.top_logprobs:
                    score_logprobs = next_token.top_logprobs
                    break
            if score_logprobs:
                break
                
    # Fallback to last token's top_logprobs if marker parsing failed
    if not score_logprobs and content_tokens:
        score_logprobs = content_tokens[-1].top_logprobs

    # Extract log-probabilities for valid integer tokens "1" through "5"
    probs: Dict[int, float] = {k: 0.0 for k in range(1, 6)}
    for lp in score_logprobs:
        t = lp.token.strip()
        if t in {"1", "2", "3", "4", "5"}:
            probs[int(t)] = math.exp(lp.logprob)
            
    total_prob = sum(probs.values())
    
    # If the model placed 100% of mass on other tokens, fallback to discrete parsing
    if total_prob == 0.0:
        raw_text = completion.choices.message.content
        for s in ["5", "4", "3", "2", "1"]:
            if f"[RESULT] {s}" in raw_text or raw_text.strip().endswith(s):
                return float(s)
        return 3.0  # Safe neutral default
        
    # G-Eval Probability-Weighted Expected Value: ∑ [ p(s_i) × s_i ]
    continuous_score = sum((p / total_prob) * s for s, p in probs.items())
    return round(continuous_score, 3)
```
